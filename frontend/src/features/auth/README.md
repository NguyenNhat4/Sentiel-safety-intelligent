# Authentication feature

Owns login, forced temporary-password replacement, and the `system_admin` account-management workspace. It calls `api/auth.ts` for account contracts and lets administrators type the responsible area name directly. The name is required for an Area Manager, trimmed before persistence, and does not need to match a pre-created monitoring zone. Account rows open the selected user's role-and-permissions editor, while their password-reset action opens Security with that same user selected. Telegram deep links remain usable until expiry even when another QR/link is generated; completing any one link consumes all outstanding challenges for that account and immediately reloads the saved account state. The role editor shows link-generation controls only while the selected account is disconnected; once linked, those controls are replaced by the single disconnect action. Disconnecting clears the stored Chat ID so future alerts no longer select that account as a recipient. The admin workspace reuses the application sidebar and provides separate tabs for account CRUD, role/area/Telegram assignment, administrator-issued password resets, and one shared active mock-camera stream. A normal user can replace a password only while `must_change_password=true`; forgotten-password recovery returns to System Admin.

After login or session restoration, `system_admin` and `safety_manager` land on Live Monitor;
only `area_manager` lands on the area dashboard. Media Library remains available to System Admin
through navigation but is never the default landing page.
